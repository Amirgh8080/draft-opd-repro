# Draft-OPD on one RTX 3090

These commands target Ubuntu x86-64, an RTX 3090 with 24 GB VRAM, and a
NVIDIA driver that supports the CUDA 12.8 stack. Plan for at least 80 GB of free disk space,
plus room for multiple training checkpoints if you run ablations.

## 1. Check the GPU and clone the code

Install [Miniconda](https://docs.anaconda.com/miniconda/) if `conda --version`
fails, then open a fresh Bash shell.

```bash
nvidia-smi --query-gpu=name,driver_version,memory.total,compute_cap --format=csv
conda --version
mkdir -p ~/draft-opd-3090
cd ~/draft-opd-3090
git clone https://github.com/Amirgh8080/draft-opd-repro.git
git clone https://github.com/Simplified-Reasoning/Draft-OPD.git
cd Draft-OPD
git checkout d6f0ec859321959785c65b59eb311fd25f042158
cp -r ../draft-opd-repro/repro .
git apply ../draft-opd-repro/patches/001-launcher-fixes.patch
git apply ../draft-opd-repro/patches/002-offline-gsm8k.patch
test -s data/apos-4000_code-5000_math-5000_gsm8k-2000_user_prompt.jsonl
```

The RTX 3090 should report compute capability 8.6. The training prompt pool is
in the pinned upstream checkout. Run the remaining commands from `Draft-OPD/`.

## 2. Create the isolated environment and cache the assets

```bash
eval "$(conda shell.bash hook)"
conda create -n draftopd3090 python=3.12 -y
conda activate draftopd3090
export CUDA_VISIBLE_DEVICES=0
export HF_HOME="$HOME/.cache/draft-opd-3090"
export WANDB_MODE=offline
bash repro/10_bootstrap_and_run.sh --env-name draftopd3090 --setup-only -y
python -c 'import torch; print(torch.__version__, torch.version.cuda, torch.cuda.get_device_name(0)); assert torch.cuda.is_bf16_supported()'
```

The bootstrap installs required Ubuntu packages and pinned Python libraries,
including the vendored SGLang and verl packages. It downloads Qwen3-4B, the
DFlash and non-thinking Draft-OPD checkpoints, and the benchmark datasets. It
also generates four validation JSONLs under `repro/data/` and writes the local
training checkpoint input paths to `repro/.state/paths.env`. Keep `HF_HOME`
the same across sessions so offline evaluation can find the cached assets.
The install log is in `repro/logs/`.

## 3. Run the smoke test and Table 1

```bash
bash repro/02_smoke_test.sh
MODE=nothinking TEMP=0.0 LOG_DIR="$PWD/repro/eval/table1-greedy" \
  bash repro/03_eval_table1.sh
MODE=nothinking TEMP=0.6 LOG_DIR="$PWD/repro/eval/table1-sampled" \
  bash repro/03_eval_table1.sh
```

The command evaluates vanilla decoding, DFlash, and Draft-OPD sequentially.
For the Qwen3-4B greedy non-thinking row, the paper's mean acceptance lengths
are 6.04 for DFlash and 6.60 for Draft-OPD. Compare acceptance length on the
same evaluation inputs and report the speedups from your own GPU. Model
revisions, dataset samples, kernels, and numerical precision can affect the
measured acceptance length. [Paper Table 1](https://arxiv.org/html/2605.29343v3#S5.T1)

For the Qwen3-4B thinking runs, cache the authors' thinking checkpoint and
provide the matching thinking-mode DFlash baseline as `DFLASH_DRAFT`.

```bash
python -c 'from huggingface_hub import snapshot_download; snapshot_download("bingyang-lei/Qwen3-4B-Thinking-Draft-OPD")'
export DFLASH_DRAFT=/absolute/path/to/matched-thinking-dflash
for temp in 0.0 0.6; do
  MODE=thinking TEMP="$temp" LOG_DIR="$PWD/repro/eval/table1-thinking-$temp" \
    bash repro/03_eval_table1.sh
done
```

The driver covers the DFlash versus Draft-OPD entries for Qwen3-4B. EAGLE-3
entries need an EAGLE-3 benchmark and matching checkpoints. Other model sizes
need their own target and matching draft checkpoints.

## 4. Measure the Table 2 serving trend

With the thinking checkpoints from step 3, run the Qwen3-4B comparison at
concurrencies 1 and 4. Read the per-concurrency output token rates and
acceptance lengths from the reports. Compute percentage gain as
`100 * (Draft-OPD tok/s / DFlash tok/s - 1)`.

```bash
MODE=thinking TEMP=0.0 CONCURRENCIES=1,4 MAX_RUNNING_REQUESTS=4 \
  DATASETS="aime25:30 math500:128 swe-bench:128" \
  LOG_DIR="$PWD/repro/eval/table2-3090" bash repro/03_eval_table1.sh
```

This is a FlashInfer measurement on one GPU. The published Table 2 uses FA3
and sweeps through concurrency 32. Start with concurrency 1 if the longer
sequences exhaust the cache. [Paper Table 2](https://arxiv.org/html/2605.29343v3#S5.T2)

## 5. Train, extract, and evaluate your drafter

```bash
unset DFLASH_DRAFT
bash repro/10_bootstrap_and_run.sh --env-name draftopd3090 --scale probe --train-only
ROLLOUT_KV_CACHE_DTYPE=fp8_e4m3 \
  bash repro/10_bootstrap_and_run.sh --env-name draftopd3090 --scale probe --train-only
bash repro/10_bootstrap_and_run.sh --env-name draftopd3090 --scale reduced --train-only
```

Start with the BF16 probe and check that an optimizer update and checkpoint
complete. The second command is an experimental FP8 rollout KV-cache run.
It uses BF16 model initialization and BF16 rollout model compute. It writes
to a different experiment directory so the probes have separate checkpoints.
The final command runs the larger BF16 experiment.

```bash
source repro/.state/paths.env
STEP_DIR="$(find "$PWD/verl/checkpoints/verl-dflash-opd/3090-reduced-kv-auto" \
  -type d -name 'global_step_*' | sort -V | tail -1)"
test -n "$STEP_DIR"
REFERENCE_DRAFT_DIR="$DRAFT_MODEL_PATH" STEP_DIR="$STEP_DIR" \
  bash repro/05_extract_draft.sh
OPD_DRAFT="$STEP_DIR/draft_model" LOG_DIR="$PWD/repro/eval/table1-local" \
  bash repro/03_eval_table1.sh
```

## 6. Run the training ablations

For the Table 3–6 comparisons, train a thinking-mode control and one checkpoint
per variant. Use an identical base checkpoint, seed, input data and budget for
each run. The following is the reduced-scale setup. Apply one override per run
and give each run a unique `EXP_NAME`.

```bash
source repro/.state/paths.env
export MAIN_MODEL_PATH DRAFT_MODEL_PATH
export ENABLE_THINKING=True SCALE=reduced
EXP_NAME=thinking-control bash repro/04_train_1gpu.sh
EXP_NAME=thinking-all-forward bash repro/04_train_1gpu.sh \
  distillation.distillation_loss.rejected_draft_use_reverse_kl=False
```

| Paper table | Variant | Change to the thinking control |
| --- | --- | --- |
| 3 | Without rejected-position decay | `REJECTED_DRAFT_POSITION_DECAY_ENABLED=False` |
| 3 | All-forward KL | `distillation.distillation_loss.rejected_draft_use_reverse_kl=False` |
| 3 | All-reverse KL | `FORWARD_KL_WEIGHT=0.0 REVERSE_KL_WEIGHT=1.0` |
| 3 | Random anchors | `RANDOM_RESPONSE_ANCHOR_ENABLED=True` |
| 4 | Naive rollout | Requires a matched target-trajectory KL-SFT baseline. There is no dedicated recipe in this harness. |
| 5 | First rejected token only | `distillation.distillation_loss.rejected_draft_first_token_only=True` |
| 6 | Accepted-position decay | `distillation.distillation_loss.accept_draft_position_decay_enabled=True` |
| 8 | Rejected-position decay sweep | `REJECTED_DRAFT_POSITION_DECAY` set to 0.95, 0.80, 0.65 and 0.50 in separate runs |
| 9 | Rejected-token weight sweep | `distillation.distillation_loss.rejected_draft_stream_weight` set to 2.0, 1.5, 1.0, 0.8 and 0.5 in separate runs |

Set uppercase or standalone shell variables before the Bash command. Pass
`distillation.distillation_loss.*` overrides after the script name. Extract
and evaluate each checkpoint as in step 5 using `MODE=thinking`, the same
`DFLASH_DRAFT`, and a unique `LOG_DIR`. Use MATH-500, HumanEval and MT-Bench
for Tables 3–4, the seven default datasets for Tables 5–6, and AIME25, MBPP,
MATH-500 and GSM8K for Tables 8–9.

Table 7 reports the authors' hardware and training budget. Table 10 requires
collecting replay diagnostics during a run with
`distillation.distillation_loss.use_replay_dis=True` and binning the
first-rejection outcomes by training half. Table 11 requires a matched
thinking/non-thinking evaluation. These analyses have no turnkey table
generator in this harness. Reduced-scale comparisons can test trends. The
paper used a larger training budget and H200 hardware. [Draft-OPD paper](https://arxiv.org/html/2605.29343v3)
